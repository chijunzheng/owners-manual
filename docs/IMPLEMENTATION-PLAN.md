## Dispatch prompt

When dispatching the next issue, populate this template and pass it to a `tdd-guide` sub-agent:

```
You are implementing GitHub issue #<N> end-to-end via the /tdd workflow.

Read in order:
1. `gh issue view <N> --comments`
2. `CONTEXT.md` (project root) — canonical glossary + resolved decisions
3. `docs/adr/<relevant ADRs>` — see `docs/adr/` if it exists
4. Existing code touching <area>: <specific file paths the orchestrator named>

Workflow: /tdd — write failing test first (RED), minimal implementation (GREEN),
refactor (IMPROVE). Verify each acceptance criterion from the issue body.

Definition of done:
- All acceptance criteria from the issue body are met
- All tests pass (existing + new)
- Lint and type checks pass
- A pull request is opened against `main` with title `<type>: <description>`
- The PR body links the issue (`Closes #<N>`)

Stop conditions (surface to orchestrator, do not proceed):
- An acceptance criterion is ambiguous or contradicts an ADR
- A blocker issue's deliverable doesn't exist in the codebase
- An architectural decision needs to be made (those go in ADRs, not in code)

Do NOT merge the PR — orchestrator owns merge.
```

The orchestrator substitutes `<N>`, `<area>`, and `<specific file paths>` per dispatch.
